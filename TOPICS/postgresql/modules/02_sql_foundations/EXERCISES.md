# Exercises: Module 02 — SQL Foundations

## Instructions

Complete each exercise in order. Exercises increase in difficulty. Submit your answers by editing this file or committing a solutions file.

---

## Easy Exercises (1–3)

### Exercise 1
**Difficulty:** Easy
**Objective:** Identify the module's core PostgreSQL vocabulary.

Write five key terms from the module and define each in one sentence.

```sql
-- Optional scratch query: identify your current session.
```

### Exercise 2
**Difficulty:** Easy
**Objective:** Run a safe read-only query.

### Exercise 3
**Difficulty:** Easy
**Objective:** Explain an error message.

Trigger one harmless PostgreSQL error in a scratch table and explain what it means.

## Medium Exercises (4–6)

### Exercise 4
**Difficulty:** Medium
**Objective:** Connect SQL syntax to data-model intent.

Write a short paragraph explaining what invariant your SQL is trying to protect.

### Exercise 5
**Difficulty:** Medium
**Objective:** Practice precise data-changing SQL.

Write an `INSERT`, `UPDATE`, or `DELETE` that uses an explicit target condition where appropriate.

### Exercise 6
**Difficulty:** Medium
**Objective:** Review tradeoffs.

Describe one decision where PostgreSQL offers more than one reasonable approach.

## Hard Exercises (7–8)

### Exercise 7
**Difficulty:** Hard
**Objective:** Debug a realistic mistake.

Create a flawed SQL statement, explain the bug, and provide the corrected version.

### Exercise 8
**Difficulty:** Hard
**Objective:** Make the work repeatable.

Write a short SQL script that can be re-run safely in a learning database.

## Expert Exercise (9)

### Exercise 9
**Difficulty:** Expert
**Objective:** Synthesize correctness and maintainability.

Write a design note explaining how this module's concepts would affect a production application.

## Theory

### Capstone Philosophy

The capstone is a planning artifact, not a promise to launch every idea in it. Professional income strategy starts by converting vague goals into explicit constraints: time available, cash at risk, tax complexity, skill fit, family obligations, ethical boundaries, and the minimum liquidity needed before experimenting. A good plan is useful even when it rejects an idea, because avoided losses are part of portfolio design.

### Portfolio Architecture

Your income portfolio should separate four layers: stable base income, experimental side gigs, semi-passive assets, and investment policy. The base layer funds essentials and protects the learner from desperate decisions. The experimental layer tests small offers with capped downside. The semi-passive layer turns repeated work into reusable assets such as templates, content libraries, rental-like systems, or delegated workflows. The investment layer defines diversified, long-horizon behavior without turning this module into personalized investment advice.

```python
# Educational capstone model: allocate attention hours across income experiments.
# The output is a planning prompt, not a recommendation.
weekly_hours = 10
allocations = {"core_job_skill": 0.30, "side_gig_test": 0.35, "system_building": 0.25, "review_admin": 0.10}
for activity, share in allocations.items():
    print(activity, round(weekly_hours * share, 1), "hours/week")
```

### Risk Review

Expert practice is mostly risk review: what can go wrong, how quickly you would notice, and what action you would take. Risks include platform bans, client nonpayment, underestimated tax obligations, uninsured liability, overconcentration in one asset, and emotional overreaction to gains or losses. Your plan must define stop-loss rules for experiments and rebalancing rules for strategy.

```csv

Cash-flow strain,Taxes not reserved from each payout,Reserve a fixed percentage in a separate account
Concentration,One income source dominates new efforts,Pause scaling and review alternatives
```

### Evidence Standards

A capstone plan should score ideas using evidence quality. A paid pilot, signed contract, audited statement, or official filing is stronger than a social media anecdote. For investing claims, prospectuses, fee schedules, risk disclosures, and historical data are stronger than influencer summaries. The learner drives the work: this module gives scaffolding, milestones, and acceptance criteria, but it does not provide a copy-paste final answer.

```python
# Educational scoring model: compare evidence quality, not just excitement.
ideas = [
    {"name": "weekend consulting", "evidence": 4, "downside": 2, "fit": 5},
    {"name": "unknown rental scheme", "evidence": 1, "downside": 5, "fit": 2},
]
for idea in ideas:
    score = idea["evidence"] + idea["fit"] - idea["downside"]
    print(idea["name"], score)
```

## Key Concepts

- **Income portfolio:** A collection of income sources with different labor needs, risks, and timelines. It is managed like a system rather than a wish list.
- **Investment policy statement:** A written set of rules for contributions, diversification, fees, rebalancing, and behavior. It prevents mood-based decisions.
- **Pilot:** A small experiment designed to test demand before large commitments. Strong pilots cap downside and produce observable evidence.
- **Maintenance load:** The recurring work required after launch. Passive claims are incomplete until maintenance is named.
- **Exit criteria:** Predefined conditions for stopping, pausing, or changing a strategy. Exit criteria protect attention and capital.

## Common Pitfalls

### Mistake: Treating the capstone as a fantasy spreadsheet

```csv
wrong_metric,value
expected_return,Guaranteed 30% monthly
risk,None
maintenance,None
```

```csv
better_metric,value
expected_return,Scenario range with evidence notes
risk,Named risks and response triggers
maintenance,Weekly tasks and owner
```

Fantasy projections feel motivating, but professional planning starts with uncertainty.

### Mistake: Scaling before validating

```python
# Wrong: spends the full budget before testing demand.
budget = 5000
pilot_spend = budget
print(pilot_spend)
```

```python
# Better: reserve most capital until evidence improves.
budget = 5000
pilot_spend = min(500, budget * 0.10)
reserve = budget - pilot_spend
print(pilot_spend, reserve)
```

### Mistake: Ignoring advice boundaries

```markdown
Wrong: "I read one module, so I will make tax and investment decisions immediately."
```

```markdown
Better: "I learned the vocabulary, prepared questions, and will verify with qualified sources before acting."
```

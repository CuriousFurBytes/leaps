# Exercises: Module 12 — Capstone Project

## Instructions
Treat these as project milestones. Do not copy a complete solution; build, test, and explain your own design.

---

## Easy Exercises (1–3)

### Exercise 1
**Difficulty:** Easy
**Objective:** Define the project boundary.

Write the service goal, inputs, outputs, and non-goals.

### Exercise 2
**Difficulty:** Easy
**Objective:** Choose interfaces.

Define the target and result data models.

### Exercise 3
**Difficulty:** Easy
**Objective:** Create a runnable skeleton.

Create a command that starts and stops cleanly.

## Medium Exercises (4–6)

### Exercise 4
**Difficulty:** Medium
**Objective:** Implement bounded concurrency.

Add a queue or semaphore so the service cannot launch unlimited work.

### Exercise 5
**Difficulty:** Medium
**Objective:** Add timeouts and retries.

Give each outbound operation a budget and clear failure state.

### Exercise 6
**Difficulty:** Medium
**Objective:** Persist useful results.

Store or export enough information to audit recent checks.

## Hard Exercises (7–8)

### Exercise 7
**Difficulty:** Hard
**Objective:** Test failure paths.

Write tests for timeout, cancellation, and partial failure.

### Exercise 8
**Difficulty:** Hard
**Objective:** Add observability.

Expose logs or metrics that explain service health.

## Expert Exercise (9)

### Exercise 9
**Difficulty:** Expert
**Objective:** Defend the design.

Write an architecture review covering tradeoffs, bottlenecks, and operational risks.

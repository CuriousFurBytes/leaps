# Exercises: Module 12 — Capstone Project

## Instructions

Complete each exercise in order. Exercises increase in difficulty. Submit your answers by editing this file or committing a solutions file.

---

## Easy Exercises (1–3)

### Exercise 1
**Difficulty:** Easy
**Objective:** Draft a product risk inventory.

List ten release risks for your chosen system and rank each from 1–5 for probability and impact.

---

### Exercise 2
**Difficulty:** Easy
**Objective:** Map tests to layers.

For each risk, choose unit, integration, E2E, regression, exploratory, or monitoring coverage.

---

### Exercise 3
**Difficulty:** Easy
**Objective:** Define acceptance criteria.

Write five observable acceptance criteria for your main user journey.

## Medium Exercises (4–6)

### Exercise 4
**Difficulty:** Medium
**Objective:** Design a unit suite.

Specify six unit checks for core business rules and explain why each is isolated.

### Exercise 5
**Difficulty:** Medium
**Objective:** Design integration coverage.

Specify four boundary tests involving persistence, APIs, queues, or third-party services.

### Exercise 6
**Difficulty:** Medium
**Objective:** Design E2E coverage.

Choose three critical journeys and define stable selectors, test data, and pass conditions.

## Hard Exercises (7–8)

### Exercise 7
**Difficulty:** Hard
**Objective:** Create regression coverage from bugs.

Invent three realistic historical bugs and write a regression test brief for each.

### Exercise 8
**Difficulty:** Hard
**Objective:** Build a CI quality gate.

Define which suites run on pull request, merge, nightly, and release candidate events.

## Expert Exercise (9)

### Exercise 9
**Difficulty:** Expert
**Objective:** Defend release confidence.

Write a one-page release recommendation explaining evidence, risks, mitigations, and go/no-go criteria.
